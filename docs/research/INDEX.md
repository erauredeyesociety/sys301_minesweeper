| [bluetooth-control-plane.md](./bluetooth-control-plane.md) | **Can we upload and manage code over Bluetooth instead of USB, and stream telemetry off an untethered robot?** LEGO's own BLE protocol reference read at source: GATT service `0000FD02-…` with hub-RX/hub-TX characteristics, write-without-response + notifications, the COBS-with-escapes/XOR-0x03/delimiter framing and standard zlib CRC32, and the complete message id table. **Upload to a slot and start/stop it do work over BLE** — but the real find is **`DeviceNotification` (id 60)**, which streams battery, IMU yaw/pitch/roll + raw accel + raw gyro, every motor's position/speed/power, the colour sensor's **raw R/G/B 0–1023** and distance in mm to the laptop at a requested interval **with no hub-side code at all** — the untethered telemetry the parked [telemetry plan](../plans/telemetry-and-analysis.md) wanted, on a robot with no cable dragging its heading. **Hub OS 3 only** (Hub OS 2 is Bluetooth Classic RFCOMM + JSON-RPC — a different stack), so it is gated on KU-M1, and a BLE scan is itself the generation test. Throughput is governed by LEGO's **stop-and-wait** chunk loop, not by MTU or framing: chunks × RTT, and the RTT is **UNMEASURED** — this host's kernel *prefers* a 30–50 ms connection interval, but no link has ever existed and the hub negotiates its own. No slot listing, no file download, no REPL over BLE — those stay USB. No released version of the VS Code extension implements either telemetry message (an **open, unmerged PR #80** would), and its BLE console readback is broken by another **open, unmerged PR #81**. **Verdict: supplement, don't replace** — dev loop stays USB, add one read-only `bleak` telemetry script, and never let a run depend on the link. Carries a four-phase go/no-go bench procedure that closes KU-M1 without a cable and never risks a Hub OS update prompt. **Nothing tested — no hardware exists** |

**Watch the API generation.** Most SPIKE tutorials online target the legacy SPIKE 2 API
(`from spike import PrimeHub`). The current API is `import motor` / `from hub import port` /
`import runloop`. Check which one a source targets before believing it.
