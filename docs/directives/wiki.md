# Wiki

**Purpose.** Usage documentation for a reader with ZERO project context arriving from the README.

- **Not yet.** There is no `docs/wiki/` and there should not be one until something ships and is
  stable. Creating one now would churn against a moving surface.
- **When it earns one:** a working robot after Demo Day, if a teammate or the instructor needs to run
  the thing without us. Then it holds: how to set up the Ubuntu host, how to deploy a program to the
  hub, how to run the mission, how to read the result — snippets for critical operations only.
- **Theory, internals, and measurements stay in `docs/research/` and `docs/findings/`.** The wiki is
  how-to, not explanation.
- **Give honest limits.** Say what the robot can't do — that is also the report's limitations section.
- **Update gate:** new milestone + stable + operator approval. Never mid-sprint.
